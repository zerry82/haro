# Context Library Gmail 사용자 시나리오

## 1. 등장인물과 상황

사용자 이름은 지윤이다.
지윤은 B2B 마케팅 운영팀의 팀장이다.
팀은 여러 광고주와 매주 메일로 업무를 주고받는다.

지윤의 문제는 메일함 안에 중요한 자료와 요청이 흩어져 있다는 점이다.
보고서 요청, 첨부파일, 일정 합의, 고객 피드백, 내부 승인 메일이 모두 Gmail thread 안에 섞여 있다.

지윤은 haro의 `메일 관리`를 사용해 최근 Gmail을 분석하고, 메일이 제대로 구조화되었는지 자연어 검색과 인사이트 질의로 테스트하려고 한다.

이번 시나리오의 핵심은 항목을 팀 지식으로 올릴지 결정하는 관리 절차가 아니다.
사용자는 “어떤 항목을 선별할지 고르는 사람”이 아니라, “haro가 메일을 업무 지식으로 잘 이해했는지 검증하는 사람”이다.

목표:

- 최근 N개 메일을 분석한다. 기본값은 50개이며 테스트 목적에 맞게 조절할 수 있다.
- 메일 thread, 첨부파일, 사람, 조직, 주제, 요청사항이 구조화되었는지 확인한다.
- 자연어로 검색해 원하는 메일과 맥락이 찾아지는지 테스트한다.
- haro에게 질문해 여러 메일에서 인사이트를 뽑아본다.
- 검색 결과와 인사이트를 보고 구조화 품질을 판단한다.
- 부족한 부분이 있으면 카테고리, 필터, 요약 기준을 조정할 후보로 남긴다.

## 2. 첫 진입

### 2.1 프로젝트 진입

1. 지윤은 haro에 로그인한다.
2. 프로젝트 목록에서 `A광고주 운영` 프로젝트를 클릭한다.
3. 프로젝트 작업공간이 열린다.
4. 왼쪽 Activity Rail에는 `폴더`, `스킬`, `툴`, `메일 관리` 아이콘이 보인다.
5. 기본 선택은 `폴더`다.
6. 중앙 영역에는 파일 뷰어가 보인다.
7. 오른쪽에는 채팅 패널이 유지된다.

### 2.2 메일 관리 메뉴 선택

1. 지윤은 왼쪽 Activity Rail에서 봉투 모양의 `메일 관리` 아이콘을 클릭한다.
2. 왼쪽 사이드 패널 제목이 `메일 관리`로 바뀐다.
3. 중앙 영역은 파일 뷰어가 아니라 `메일 관리 워크벤치`로 전환된다.
4. 중앙 영역에는 더 이상 “파일을 선택하세요”가 보이지 않는다.
5. 오른쪽 채팅 패널은 그대로 유지된다.

이때 화면은 세 영역으로 나뉜다.

| 영역 | 지윤이 보는 내용 |
| --- | --- |
| 왼쪽 사이드 패널 | Gmail 연결 상태, 마지막 분석, 구조화 품질 테스트 상태, 내부 메뉴 |
| 중앙 메인 영역 | 메일 관리 개요와 다음에 해야 할 테스트 |
| 오른쪽 채팅 패널 | haro에게 자연어로 검색하거나 인사이트를 요청하는 채팅 |

왼쪽 사이드 패널은 설정 폼이 아니라 메일 관리의 목차와 상태 요약이다.

예:

```text
Gmail
연결 안 됨

최근 분석
아직 없음

구조화 테스트
미실행
```

## 3. Gmail 연결

### 3.1 미연결 상태

처음 들어오면 중앙 영역에는 `Gmail을 연결하세요` 화면이 보인다.

화면에 표시되는 정보:

- Gmail은 읽기 전용으로 연결된다는 설명
- 원문 메일이 곧바로 팀 지식으로 저장되지 않는다는 안내
- 최근 N개 메일을 먼저 분석하고 구조화 품질을 테스트한다는 설명
- `Gmail 연결` 버튼

보여주지 않는 것:

- 필터 편집 폼
- 검색 테스트 화면
- 의미 없는 0개 통계 카드

### 3.2 연결 버튼 클릭

1. 지윤은 중앙 영역의 `Gmail 연결` 버튼을 클릭한다.
2. Google OAuth 연결 화면이 열린다.
3. 지윤은 회사 Gmail 계정 `jiyoon@agency.com`을 선택한다.
4. 권한 화면에서 읽기 전용 권한을 확인한다.
5. 지윤은 `허용`을 클릭한다.
6. haro 화면으로 돌아온다.

연결 성공 후 중앙 영역은 `Gmail 연결 완료` 상태를 보여준다.

표시되는 정보:

```text
연결 계정: jiyoon@agency.com
권한: 읽기 전용
마지막 동기화: 아직 없음
다음 단계: 최근 50개 분석
```

주요 버튼:

- `최근 50개 분석 시작`
- `Gmail 다시 가져오기`
- 분석 개수 입력값 기본값 `50`
- `연결 해제`
- `권한 다시 확인`

왼쪽 사이드 패널의 주요 CTA도 `최근 50개 분석`으로 바뀌고, 옆에서 분석 개수를 조절할 수 있다.

## 4. 최근 N개 분석

### 4.1 분석 시작

1. 지윤은 분석 개수가 `50`인지 확인한다.
2. 테스트 범위를 줄이고 싶으면 개수 입력을 `20`처럼 바꾼다.
3. 지윤은 중앙 영역의 `최근 50개 분석 시작` 버튼을 클릭한다.
4. 이미 저장된 snapshot이 있으면 haro는 Gmail을 다시 호출하지 않고 캐시된 thread로 분석한다.
5. Gmail에서 최신 메일을 다시 받아오고 싶을 때는 `Gmail 다시 가져오기`를 클릭한다.
6. haro는 즉시 분석 run을 만들고, 화면은 run status를 polling한다.
7. 분석 진행 화면이 열린다.
8. 진행 단계가 순서대로 표시된다.

진행 단계:

```text
1. 분석 작업 대기 중
2. Gmail snapshot 수집 중
3. thread 정규화 중
4. LLM 구조화 중
5. 검색 가능한 구조로 저장 중
6. 완료 또는 실패
```

각 단계에는 성공, 진행 중, 실패 상태가 표시된다.
실패하면 실패 stage와 재시도 버튼이 표시된다.
LLM 구조화 batch가 실패한 경우에는 전체 분석을 멈추지 않고 해당 thread에 구조화 주의 이유와 낮은 confidence를 남긴다.

### 4.2 분석 완료

분석이 끝나면 중앙 영역은 `최근 분석` 화면으로 이동한다.

상단 요약 카드:

```text
분석 대상: 최신 thread 50개
전체 thread: 50개
구조화 완료 thread: 121개
구조화 주의 필요: 7개
첨부파일: 36개
요약 가능 첨부: 21개
추출된 요청사항: 58개
추출된 일정: 19개
카테고리 후보: 6개
```

왼쪽 사이드 패널도 업데이트된다.

```text
최근 분석
방금 완료

구조화 테스트
대기 중
```

중앙 영역의 다음 CTA는 `구조화 테스트 시작`이다.

## 5. 1차 구조화 결과 확인

### 5.1 보낸사람 통계 보기

1. 지윤은 `최근 분석` 화면에서 `보낸사람` 탭을 클릭한다.
2. 보낸사람별 thread 수와 추출된 업무 맥락이 표로 표시된다.

표 컬럼:

- 보낸사람
- 도메인
- thread 수
- 추출된 요청사항 수
- 첨부 수
- 대표 카테고리
- 구조화 품질

예시:

| 보낸사람 | 도메인 | thread 수 | 요청사항 | 첨부 | 대표 카테고리 | 품질 |
| --- | --- | ---: | ---: | ---: | --- | --- |
| 김민지 매니저 | client-a.com | 18 | 14 | 7 | 성과 보고 | 좋음 |
| 박준호 대리 | media-partner.co.kr | 12 | 6 | 4 | 매체 운영 | 보통 |
| newsletter@vendor.com | vendor.com | 34 | 0 | 0 | 뉴스레터 | 제외 적합 |

지윤은 client-a.com 메일은 요청사항이 잘 추출됐지만, media-partner.co.kr 메일은 품질이 `보통`으로 표시된 것을 확인한다.

### 5.2 카테고리 분포 보기

1. 지윤은 `카테고리` 탭을 클릭한다.
2. haro가 제안한 카테고리와 구조화 품질이 보인다.

예시:

| 카테고리 | thread 수 | 요청사항 | 일정 | 첨부 | 구조화 품질 |
| --- | ---: | ---: | ---: | ---: | --- |
| 성과 보고 | 21 | 18 | 7 | 12 | 좋음 |
| 일정/회의 | 17 | 9 | 12 | 3 | 좋음 |
| 계약/정산 | 9 | 6 | 1 | 5 | 보통 |
| 자료/레퍼런스 | 14 | 4 | 0 | 13 | 좋음 |
| 뉴스레터 | 34 | 0 | 0 | 0 | 제외 적합 |
| 일반 업무 | 33 | 21 | 4 | 3 | 주의 |

지윤은 `일반 업무`에 요청사항이 21개나 잡혀 있는 것을 보고, 분류가 너무 넓다고 판단한다.
하지만 이 단계에서는 바로 재분류하지 않고, 자연어 검색으로 실제로 원하는 답이 나오는지 먼저 테스트하기로 한다.

### 5.3 thread 목록 보기

1. 지윤은 `Thread` 탭을 클릭한다.
2. 최근 50개 thread 목록이 표시된다.

표 컬럼:

- 구조화 상태
- 카테고리
- 제목
- 보낸사람
- 받은사람
- 수신일
- 추출된 요청사항
- 추출된 일정
- 첨부 수
- 요약

예시:

```text
좋음 | 성과 보고 | [A광고주] 5월 2주차 성과 보고 요청
보낸사람: 김민지 <mj@client-a.com>
요청사항: 금요일까지 주간 성과 보고서와 다음 주 액션 플랜 작성
일정: 2026-05-16 17:00
첨부: performance_202605.xlsx
```

```text
주의 | 일반 업무 | 캠페인 소재 관련해서 확인 부탁드립니다
보낸사람: 박준호 <junho@media-partner.co.kr>
요청사항: 소재 상태 확인으로 추정
일정: 없음
첨부: banner.zip
주의 이유: 요청 주체와 기대 결과물이 불명확함
```

지윤은 `주의` 항목을 몇 개 열어본 뒤, 자연어 검색 테스트에서 이 항목들이 어떻게 걸리는지 보기로 한다.
각 thread 상세에서는 요약, 요청사항, 일정뿐 아니라 snapshot에 저장된 메일 본문 전문과 첨부파일 목록도 함께 확인한다.
본문이 길면 snapshot 저장 한도까지 표시되고, 첨부파일은 사용자 `00_inbox`에 저장된 경로, 확장자, 용량, mime type, 추출 상태, 가능한 요약으로 표시된다.
뉴스레터나 광고 메일처럼 HTML 레이아웃이 중요한 메일은 `원본` 보기에서 sandbox 렌더러로 확인하고, 필요한 경우 `텍스트` 보기로 전환해 추출된 본문을 비교한다.

## 6. 첨부파일 구조화 확인

1. 지윤은 `첨부파일` 탭을 클릭한다.
2. 최근 50개 메일에서 발견된 첨부파일 목록이 표시된다.

표 컬럼:

- 파일 제목
- 확장자
- 용량
- 연결 thread
- 보낸사람
- 요약 가능 여부
- 요약 상태
- 추출된 핵심 내용

예시:

| 파일 제목 | 확장자 | 용량 | thread | 요약 상태 | 핵심 내용 |
| --- | --- | ---: | --- | --- | --- |
| performance_202605.xlsx | xlsx | 1.4MB | 성과 보고 요청 | 완료 | 캠페인별 노출, 클릭, 전환, CPA 지표 |
| meeting_notes.pdf | pdf | 680KB | 주간 회의록 공유 | 완료 | 회의 결정사항과 액션 아이템 |
| banner.zip | zip | 12MB | 소재 전달 | 요약 제외 | zip 파일은 v1 요약 제외 |

지윤은 zip 파일은 내용 요약 대상이 아니라는 점을 확인한다.
이 정보는 나중에 “첨부파일 기반 검색이 어디까지 가능한가”를 판단하는 근거가 된다.

## 7. 구조화 테스트 시작

### 7.1 테스트 화면 이동

1. 지윤은 왼쪽 사이드 패널에서 `구조화 테스트`를 클릭한다.
2. 중앙 영역이 자연어 검색과 인사이트 테스트 화면으로 바뀐다.

상단에는 테스트 목적이 표시된다.

```text
최근 분석 결과가 업무 지식으로 잘 구조화되었는지 확인합니다.
자연어로 검색하거나 질문해 원하는 thread, 요청사항, 첨부, 일정, 인사이트가 나오는지 테스트하세요.
```

테스트 화면은 세 영역으로 구성된다.

| 영역 | 역할 |
| --- | --- |
| 자연어 검색창 | 사용자가 자유롭게 질문을 입력 |
| 테스트 추천 질문 | haro가 품질 확인용 질문을 제안 |
| 결과/인사이트 패널 | 검색 결과, 근거 thread, 추출된 인사이트 표시 |

### 7.2 추천 테스트 질문 확인

haro는 지윤에게 테스트 질문을 제안한다.

예:

```text
- 이번 주 A광고주가 요청한 성과 보고 관련 메일 찾아줘
- 금요일까지 해야 하는 요청만 모아줘
- 첨부파일이 있는 고객 요청만 보여줘
- client-a.com에서 온 메일 중 액션 플랜을 요구한 것만 찾아줘
- 일정이 명확하지 않은 요청을 보여줘
- 이번 주 고객들이 반복해서 요구한 것은 뭐야?
- 첨부된 엑셀 파일들이 어떤 지표를 담고 있는지 요약해줘
```

지윤은 이 추천 질문을 하나씩 클릭해 구조화 품질을 확인한다.

## 8. 자연어 검색 테스트

### 8.1 고객별 요청 검색

지윤은 검색창에 입력한다.

```text
이번 주 A광고주가 요청한 성과 보고 관련 메일 찾아줘
```

haro는 검색 결과를 보여준다.

결과 예:

```text
검색 결과 3개

1. [A광고주] 5월 2주차 성과 보고 요청
   보낸사람: 김민지 <mj@client-a.com>
   카테고리: 성과 보고
   요청사항: 금요일 17시까지 주간 성과 보고서와 다음 주 액션 플랜 작성
   첨부: performance_202605.xlsx
   근거: 제목, sender domain, 요청사항 추출, 첨부 요약

2. Re: [A광고주] 리포트 코멘트 반영
   보낸사람: 김민지 <mj@client-a.com>
   카테고리: 성과 보고
   요청사항: 전환율 하락 원인과 개선 액션 추가
   근거: 본문 요약, thread 연결

3. [A광고주] 다음 주 캠페인 액션 플랜 논의
   보낸사람: 김민지 <mj@client-a.com>
   카테고리: 일정/회의
   요청사항: 다음 주 캠페인 액션 플랜 회의 일정 조율
   근거: 제목, 일정 추출
```

지윤이 확인하는 기준:

- `A광고주`라는 표현이 sender domain과 thread 내용으로 잘 연결되는가
- `성과 보고`와 `액션 플랜`이 같은 업무 맥락으로 묶이는가
- 검색 결과에 뉴스레터나 무관한 메일이 끼지 않는가
- 결과마다 근거가 보이는가

판단:

```text
검색 품질: 좋음
무관 결과: 없음
근거 표시: 충분함
```

### 8.2 일정 기반 검색

지윤은 다음 질문을 입력한다.

```text
금요일까지 해야 하는 요청만 모아줘
```

haro는 일정이 추출된 요청을 보여준다.

결과 예:

| 요청 | 고객/보낸사람 | 마감 | 근거 |
| --- | --- | --- | --- |
| 주간 성과 보고서 작성 | A광고주 김민지 | 2026-05-16 17:00 | 본문 “금요일 오후 5시까지” |
| 캠페인 소재 상태 확인 | B광고주 이수연 | 2026-05-16 오전 | 본문 “금요일 오전 중” |
| 견적서 수정본 회신 | C광고주 최현우 | 2026-05-16 | 제목과 본문 |

지윤이 확인하는 기준:

- 날짜 표현이 실제 날짜로 정규화되는가
- “금요일까지”, “이번 주 안에”, “오전 중” 같은 표현이 잘 잡히는가
- 마감이 없는 요청이 섞이지 않는가

판단:

```text
검색 품질: 보통
주의: “이번 주 안에”가 일부 항목에서 마감일로 잡히지 않음
개선 후보: 상대 날짜 표현 정규화 강화
```

### 8.3 첨부파일 기반 검색

지윤은 다음 질문을 입력한다.

```text
첨부된 엑셀 파일들이 어떤 지표를 담고 있는지 요약해줘
```

haro는 xlsx, xls, csv 첨부 요약을 모아 답한다.

응답 예:

```text
최근 50개 엑셀/CSV 첨부 8개를 확인했습니다.

주요 지표:
- 캠페인별 노출, 클릭, CTR, CPC, 전환, CPA
- 매체별 예산 소진율
- 키워드별 전환 성과
- 소재별 클릭률

가장 많이 등장한 지표:
1. 클릭/CTR: 6개 파일
2. 전환/CPA: 5개 파일
3. 예산 소진율: 4개 파일

대표 첨부:
- performance_202605.xlsx: A광고주 주간 성과
- naver_keyword_report.csv: 키워드별 전환 성과
- media_spend.xlsx: 매체별 예산 소진율
```

지윤이 확인하는 기준:

- 첨부파일 제목이 아니라 내용 요약 기반으로 답하는가
- 엑셀/CSV만 잘 필터링되는가
- 어느 thread에 붙어 있던 파일인지 추적 가능한가

판단:

```text
검색 품질: 좋음
첨부 요약: 충분함
추적성: 파일별 연결 thread가 보여야 더 좋음
```

### 8.4 모호한 요청 검색

지윤은 다음 질문을 입력한다.

```text
요청은 있는데 일정이나 결과물이 불명확한 메일 보여줘
```

haro는 구조화 주의 항목을 보여준다.

결과 예:

```text
주의 필요 요청 7개

1. 캠페인 소재 관련해서 확인 부탁드립니다
   불명확한 점: 확인해야 할 대상이 소재 승인인지, 게재 상태인지 명확하지 않음
   일정: 없음
   추천 후속 질문: 어떤 소재의 어떤 상태를 확인하면 될까요?

2. 지난번 이야기한 건 진행 가능할까요?
   불명확한 점: "지난번 이야기한 건"의 참조 대상이 thread 안에서 확정되지 않음
   일정: 없음
   추천 후속 질문: 어떤 업무 건을 말씀하시는지 확인 필요
```

지윤이 확인하는 기준:

- 불명확한 요청을 무리하게 확정하지 않는가
- 누락 정보가 무엇인지 설명하는가
- 후속 질문 후보가 실무적으로 쓸 만한가

판단:

```text
검색 품질: 좋음
신뢰도: 높음
이 기능은 실제 업무 인박스에도 유용함
```

## 9. 인사이트 추출 테스트

### 9.1 반복 요청 인사이트

지윤은 오른쪽 채팅 패널에 입력한다.

```text
이번 주 고객들이 반복해서 요구한 것은 뭐야?
```

haro는 여러 thread를 묶어 인사이트를 생성한다.

응답 예:

```text
최근 50개 고객 요청에서 반복된 패턴은 4가지입니다.

1. 성과 보고서에 다음 액션 플랜을 함께 요구
   - A광고주, B광고주, D광고주에서 반복
   - 단순 수치 보고보다 "다음 주에 무엇을 할지"를 요구하는 흐름

2. 전환율 하락 원인 설명 요청
   - A광고주와 C광고주에서 등장
   - 첨부된 성과표에서 CPA 상승, 전환율 하락 지표가 함께 관찰됨

3. 소재 상태 확인 요청
   - B광고주와 매체 파트너 thread에서 반복
   - 요청은 많지만 일정이 불명확한 경우가 있음

4. 금요일 마감 요청 집중
   - 명시 마감 19개 중 11개가 금요일
   - 주간 리포트 업무가 금요일 오후에 몰리는 패턴
```

지윤이 확인하는 기준:

- 단순 검색 결과 나열이 아니라 반복 패턴을 요약하는가
- 여러 고객과 thread를 연결해 말하는가
- 첨부파일 지표와 메일 요청을 함께 해석하는가
- 근거 thread가 표시되는가

판단:

```text
인사이트 품질: 좋음
활용 가능성: 주간 회의 안건으로 바로 쓸 수 있음
```

### 9.2 고객별 리스크 인사이트

지윤은 입력한다.

```text
이번 주 A광고주 관련해서 놓치면 위험한 게 뭐야?
```

haro는 A광고주 thread만 묶어 답한다.

응답 예:

```text
A광고주 관련 주의할 점은 3가지입니다.

1. 금요일 17시 성과 보고 마감
   - 명시 마감이 있음
   - 요청자는 김민지 매니저
   - 첨부 performance_202605.xlsx를 보고서 근거로 써야 함

2. 전환율 하락 원인 설명 필요
   - 리포트 코멘트 thread에서 추가 요청됨
   - 단순 수치 나열보다 원인과 개선 액션을 요구

3. 다음 주 액션 플랜 회의 일정 미확정
   - 일정 조율 thread가 있으나 확정 시간이 없음
   - 후속 확인 필요
```

지윤이 확인하는 기준:

- A광고주 관련 메일만 정확히 모았는가
- 마감, 요청자, 첨부, 후속 액션이 함께 나오는가
- “위험”을 과장하지 않고 업무 누락 가능성 중심으로 설명하는가

판단:

```text
인사이트 품질: 좋음
다음 액션: A광고주 업무 체크리스트 생성에 활용 가능
```

### 9.3 구조화 오류 찾기

지윤은 입력한다.

```text
구조화가 애매하거나 자신 없는 항목만 보여줘
```

haro는 confidence가 낮거나 누락 정보가 있는 항목을 보여준다.

응답 예:

```text
구조화 주의 항목 7개를 찾았습니다.

주요 원인:
- thread 안의 대명사 참조가 불명확함: 3개
- 결과물이 명확하지 않음: 2개
- 일정 표현이 상대적이지만 기준일이 애매함: 1개
- 첨부파일이 zip이라 내용 요약 불가: 1개

대표 항목:
1. "지난번 이야기한 건 진행 가능할까요?"
   - 참조 대상 불명확
   - 추천: 이전 thread 연결 강화 필요

2. "소재 관련해서 확인 부탁드립니다"
   - 결과물 불명확
   - 추천: 소재 승인/게재/수정 중 어떤 확인인지 구분 필요
```

지윤이 확인하는 기준:

- haro가 모르는 것을 모른다고 표시하는가
- 구조화 실패 원인이 설명되는가
- 개선할 기준이 보이는가

판단:

```text
신뢰도: 좋음
개선 후보: 이전 thread 참조와 소재 업무 카테고리 강화
```

## 10. 구조화 테스트 결과 정리

지윤은 `테스트 결과` 탭을 클릭한다.
화면에는 자연어 검색과 인사이트 테스트 결과가 요약된다.

예시:

```text
테스트 질문: 8개
성공: 6개
주의: 2개
실패: 0개

잘 된 점:
- 고객별 요청 검색

- 마감 있는 요청 검색
- 모호한 요청 탐지
- 반복 요청 인사이트

주의할 점:
- "이번 주 안에" 같은 상대 날짜 정규화
- 소재 관련 메일의 결과물 구분
```

이 개선 후보는 즉시 구조를 바꾸는 작업이 아니다.
다음 스킬/규칙 개선이나 프롬프트 개선의 입력으로 남는다.

## 11. 오른쪽 채팅 패널 활용

메일 관리 중에도 오른쪽 채팅 패널은 유지된다.
지윤은 채팅으로 haro에게 다음처럼 요청할 수 있다.

메일 목록에서 thread를 선택한 상태라면 채팅 입력창 위에는 현재 컨텍스트가 표시된다.

```text
메일: [A광고주] 5월 2주차 성과 보고 요청
선택한 메일에 대해 질문하세요...
```

이 상태에서 메시지를 보내면 haro는 최신 completed 분석 run과 선택 thread를 함께 참조한다.
사용자 메시지에도 작은 `메일:` 표시가 남아, 나중에 대화 이력을 볼 때 어떤 메일을 기준으로 질문했는지 알 수 있다.
채팅 입력의 `워크벤치에서 보기`를 누르면 지윤은 다시 `메일 관리` 워크벤치로 돌아온다.

예시 1:

```text
이번 주 A광고주가 성과 보고와 관련해서 요청한 것만 찾아줘.
```

haro는 구조화된 thread, 요청사항, 일정, 첨부 요약을 근거와 함께 보여준다.

예시 2:

```text
이번 분석에서 구조화가 애매한 메일만 모아서 이유별로 정리해줘.
```

haro는 confidence가 낮은 항목을 원인별로 묶어 보여준다.

예시 3:

```text
고객들이 반복적으로 요청한 걸 기준으로 다음 주 업무 리스크를 알려줘.
```

haro는 여러 thread를 묶어 반복 요청과 마감 집중도를 인사이트로 정리한다.

예시 4:

```text
첨부파일이 있는 메일 중 보고서 작성에 쓸 만한 자료만 찾아줘.
```

haro는 xlsx, csv, pdf 등 요약 가능한 첨부를 중심으로 결과를 보여준다.

## 12. 마무리 시나리오

지윤은 구조화 테스트를 마친 뒤 `테스트 결과` 화면으로 돌아온다.

1. 지윤은 성공한 테스트와 주의가 필요한 테스트를 다시 확인한다.
2. `개선 후보` 목록을 열어본다.
3. 다음 개선 작업으로 넘길 항목을 선택한다.

예:

```text
다음 개선 후보
- 상대 날짜 표현 정규화 강화
- 소재 관련 메일의 결과물 구분
- media-partner.co.kr 메일의 요청사항 추출 품질 개선
- zip 첨부파일은 내용 검색이 아니라 메타데이터 검색으로 명확히 표시
```

4. 지윤은 오른쪽 채팅에 마지막으로 묻는다.

```text
오늘 분석한 메일 구조화에서 가장 먼저 개선해야 할 기준은 뭐야?
```

5. haro는 테스트 결과와 주의 항목을 근거로 답한다.

```text
가장 먼저 개선할 기준은 소재 관련 메일의 결과물 구분입니다.
주의 항목 7개 중 3개가 소재 확인 요청이고, 승인/게재/수정 중 무엇을 확인해야 하는지 불명확했습니다.
이 카테고리를 분리하면 자연어 검색과 업무 리스크 인사이트 품질이 가장 크게 좋아질 가능성이 높습니다.
```

6. 지윤은 이 내용을 다음 스킬/규칙 개선 작업의 입력으로 남긴다.

## 13. 성공적인 경험의 기준

지윤은 이 기능을 사용한 뒤 다음을 느껴야 한다.

- 메일함 전체를 뒤지는 부담이 줄었다.
- haro가 메일을 어떤 구조로 이해했는지 볼 수 있다.
- 자연어 검색으로 원하는 thread와 요청사항을 찾을 수 있다.
- 여러 메일을 묶어 반복 요청, 마감 집중, 고객별 리스크 같은 인사이트를 얻을 수 있다.
- 구조화가 애매한 항목도 숨기지 않고 보여준다.
- 원문 메일이 무작정 팀 폴더에 들어가지 않아 안심된다.
- 다음 단계에서 어떤 카테고리, 필터, 요약 기준을 개선해야 할지 알 수 있다.
