# Context Library Gmail UI 설계

## 1. 설계 목표

`메일 관리` UI의 목적은 Gmail을 단순히 연결하고 목록을 보여주는 것이 아니다.
사용자가 최근 Gmail이 업무 지식으로 얼마나 잘 구조화되었는지 직접 확인하고, 자연어 검색과 인사이트 질의로 품질을 테스트하게 만드는 것이다.

따라서 UI는 다음 경험을 중심으로 설계한다.

- 메일이 분석되기 전과 후의 상태가 명확하다.
- 사용자는 현재 단계와 다음 행동을 바로 알 수 있다.
- 중앙 영역은 파일 뷰어가 아니라 채팅과 상호작용하는 메일 관리 워크벤치가 된다.
- 왼쪽 패널은 메일 목록과 선택한 메일 상세를 확인하는 탐색 영역이다.
- `개요`, `최근 분석`, `구조화 테스트`, `자연어 검색`, `인사이트`, `테스트 결과`는 중앙 워크벤치 상단 메뉴로 제공한다.
- 자연어 검색과 인사이트 결과에는 항상 근거가 보인다.
- 구조화가 애매한 항목은 숨기지 않고 “주의”로 드러낸다.
- 최종 산출은 “개선 후보”다.

## 2. 전체 레이아웃

메일 관리 선택 시 화면은 기존 프로젝트 작업공간 안에서 다음 구조로 전환된다.

```text
┌───────────────────────────────────────────────────────────────────────┐
│ Top Bar                                                               │
├──────┬──────────────────────┬──────────────────────────────┬─────────┤
│ Rail │ Mail List/Detail     │ Interactive Mail Workbench    │ Chat    │
│      │ Panel                │                              │ Panel   │
└──────┴──────────────────────┴──────────────────────────────┴─────────┘
```

### Activity Rail

역할:

- `메일 관리` 아이콘 선택 상태 표시
- 다른 영역으로 이동하는 전역 내비게이션 유지

메일 관리 아이콘을 클릭하면:

- 왼쪽 사이드 패널 제목이 `메일 관리`로 바뀌고 메일 목록을 보여준다.
- 중앙 영역은 `Mail Workbench`로 바뀐다.
- 중앙 영역에 “파일을 선택하세요”가 표시되지 않는다.
- 오른쪽 채팅 패널은 유지된다.

### Mail Side Panel

역할:

- Gmail 연결/분석 상태 요약
- 최근 분석된 메일 thread 목록 표시
- 메일 검색/필터
- 선택한 메일의 상세 요약 표시
- 선택한 메일을 중앙 워크벤치와 채팅 컨텍스트에 연결

하지 말아야 할 것:

- Gmail 연결 폼 전체를 넣지 않는다.
- 상단 메뉴 역할을 하지 않는다.
- 자연어 검색 결과 전체를 넣지 않는다.
- 인사이트 결과 전체를 넣지 않는다.
- 긴 분석 대시보드를 넣지 않는다.

### Mail Workbench

역할:

- 상단 메뉴로 `개요`, `최근 분석`, `구조화 테스트`, `자연어 검색`, `인사이트`, `테스트 결과` 전환
- 선택된 메일과 채팅 질문을 함께 반영
- 자연어 검색 결과를 표/카드/근거로 표시
- 인사이트 결과를 구조화된 리포트처럼 표시
- 테스트 결과와 개선 후보 정리

이 영역이 메일 관리의 주 화면이다.

### Chat Panel

역할:

- 사용자가 자연어로 검색하거나 인사이트를 요청하는 보조 채널
- 현재 Mail Workbench의 분석 run을 참조해 답변
- 왼쪽에서 선택한 메일을 현재 대화 컨텍스트로 참조
- 검색 결과나 인사이트를 중앙 워크벤치와 연결

채팅은 유지하지만, 메일 관리의 핵심 조작은 중앙 워크벤치에서 가능해야 한다.

## 3. Mail Side Panel 설계

### 기본 구조

```text
메일 관리

Gmail
연결됨 / 연결 안 됨
jiyoon@agency.com

[주요 CTA]

[메일 검색]

필터
전체 / 주의 / 첨부 있음 / 일정 있음

메일 목록
┌ thread row ┐
┌ thread row ┐
┌ thread row ┐

선택한 메일 상세
제목
보낸사람
요약
요청사항
일정
첨부
```

### 상태 요약 규칙

Gmail 미연결:

```text
Gmail
연결 안 됨

[Gmail 연결]
```

연결 후 분석 전:

```text
Gmail
연결됨
jiyoon@agency.com

[최근 50개 분석] [개수 50]
```

분석 후 테스트 전:

```text
Gmail
연결됨
jiyoon@agency.com

메일 목록
50개 thread
주의 7개
첨부 있음 36개

[구조화 테스트 시작]
```

테스트 후:

```text
메일 목록
50개 thread
현재 선택: A광고주 성과 보고 요청

최근 테스트
성공 6
주의 2
```

### 메일 목록

메일 목록은 최근 분석된 thread를 보여준다.
이 목록은 상단 메뉴와 별개로 항상 유지된다.

thread row에 필요한 정보:

- 구조화 상태 badge
- 보낸사람 또는 조직
- 제목
- 짧은 요약
- 요청사항 수
- 일정 여부
- 첨부 여부
- 수신일

예:

```text
[주의] 박준호
캠페인 소재 관련해서 확인 부탁드립니다
요청 1 · 일정 없음 · 첨부 1
```

목록 필터:

- 전체
- 구조화 좋음
- 주의 필요
- 첨부 있음
- 일정 있음
- 요청사항 있음

목록 검색:

- 제목
- 보낸사람
- 도메인
- 카테고리
- 첨부파일명

### 메일 상세

메일 목록에서 thread를 클릭하면 같은 왼쪽 패널 하단 또는 접이식 상세 영역에 메일 상세가 열린다.
상세는 구조화 요약을 먼저 보여주되, 사용자가 검증할 수 있도록 snapshot에 저장된 메일 본문과 첨부파일 정보도 함께 제공한다.
HTML 메일은 원본 렌더러와 텍스트 fallback을 전환할 수 있어야 한다.

메일 상세에 필요한 요소:

- 제목
- 보낸사람
- 받은사람
- 수신일
- 카테고리
- 구조화 상태
- 요약
- 메일 본문 전문 또는 snapshot이 없을 때의 본문 일부
- HTML 원본 렌더러/텍스트 보기 전환
- 추출된 요청사항
- 추출된 일정
- 첨부파일 저장 경로, 다운로드 상태, 추출 상태, 가능한 파일 요약
- 구조화 주의 이유
- 근거 보기 버튼
- `이 메일로 질문하기` 버튼

`이 메일로 질문하기`를 클릭하면:

- 오른쪽 채팅 입력에 선택 메일 컨텍스트가 붙는다.
- 중앙 워크벤치의 현재 탭은 유지된다.
- 채팅 placeholder가 “선택한 메일에 대해 질문하세요”로 바뀐다.

예:

```text
선택 메일
[A광고주] 5월 2주차 성과 보고 요청

요약
A광고주 김민지 매니저가 금요일 오후 5시까지 주간 성과 보고서와 다음 주 액션 플랜을 요청했다.

본문
김민지 매니저가 보낸 메일 본문을 snapshot 한도 내에서 그대로 표시한다.

요청사항
- 주간 성과 보고서 작성
- 다음 주 액션 플랜 포함

일정
- 2026-05-16 17:00

첨부
- performance_202605.xlsx
```

## 4. Mail Workbench 공통 구조

모든 메일 관리 화면은 다음 레이아웃을 공유한다.

```text
┌─────────────────────────────────────────────┐
│ Top Menu                                    │
│ 개요 · 최근 분석 · 구조화 테스트 · 검색 ... │
├─────────────────────────────────────────────┤
│ Context Bar                                 │
│ 선택 메일 / 현재 질문 / 분석 run            │
├─────────────────────────────────────────────┤
│ Interactive Content                         │
├─────────────────────────────────────────────┤
│ Result / Evidence / Improvement Area        │
└─────────────────────────────────────────────┘
```

### Top Menu

상단 메뉴는 메일 관리 내부 화면을 전환한다.
왼쪽 사이드 패널에 있던 내부 메뉴는 모두 상단으로 이동한다.

메뉴:

- `개요`
- `최근 분석`
- `구조화 테스트`
- `자연어 검색`
- `인사이트`
- `테스트 결과`

동작:

- 현재 선택된 메뉴를 강조한다.
- 분석 전에는 `구조화 테스트`, `자연어 검색`, `인사이트`, `테스트 결과`를 disabled로 표시한다.
- disabled 메뉴에는 “최근 메일 분석 후 사용할 수 있습니다” tooltip을 제공한다.
- 상단 메뉴 아래에는 현재 화면 제목과 주요 CTA를 표시한다.
- 분석 시작 후에는 완료 응답을 기다리는 정지 화면이 아니라 run status polling 상태를 표시한다.
- 진행 문구는 `수집 중`, `정규화 중`, `LLM 구조화 중`, `저장 중`, `완료`, `실패`를 사용한다.
- 실패 상태에는 실패 stage와 재시도 CTA를 같이 표시한다.

예:

```text
[개요] [최근 분석] [구조화 테스트] [자연어 검색] [인사이트] [테스트 결과]
```

### Context Bar

상단 메뉴 아래에는 현재 작업 맥락을 얇게 표시한다.

포함 요소:

- 현재 분석 run
- 분석 대상 개수
- 선택된 메일 thread
- 오른쪽 채팅에서 실행한 최근 질문
- 구조화 상태 요약

예:

```text
분석 대상: 최신 thread 50개
선택 메일: [A광고주] 5월 2주차 성과 보고 요청
최근 질문: 금요일까지 해야 하는 요청만 모아줘
```

### Progress or Summary Strip

분석 전:

- 다음 단계 안내

분석 중:

- 단계별 진행 상태
- 현재 run id
- cache-first 또는 Gmail 다시 가져오기 여부
- LLM 구조화 stage와 fallback warning 수

분석 후:

- 핵심 지표 요약

테스트 후:

- 성공/주의/실패 요약

### Detail Panel

thread, 첨부파일, 검색 결과, 인사이트 근거를 클릭하면 중앙 워크벤치 내부의 result/evidence 영역에 상세가 열린다.
메일 원본/요약 상세는 왼쪽 Mail Side Panel의 메일 상세와 연결된다.

상세 패널에는 다음이 포함된다.

- 원본 제목
- 구조화 요약
- 추출된 필드
- 근거
- 품질 상태
- 개선 후보 저장 액션

## 5. 화면별 UI 설계

## 5.1 개요

### 목적

사용자가 지금 무엇을 해야 하는지 빠르게 판단하는 시작 화면이다.

### 연결 전

중앙에 큰 연결 영역을 둔다.

```text
Gmail을 연결하세요

최근 N개 메일을 분석해 thread, 요청사항, 일정, 첨부파일을 구조화합니다.
기본값은 50개이며 테스트 목적에 맞게 개수를 조절할 수 있습니다.
분석 후 자연어 검색과 인사이트 질문으로 구조화 품질을 테스트할 수 있습니다.

[Gmail 연결]
```

보조 설명:

- 읽기 전용 권한
- 원문 메일은 자동으로 팀 폴더에 저장되지 않음
- 분석 결과는 구조화 테스트용으로 사용됨

### 연결 후 분석 전

중앙 워크벤치 상단 메뉴에서 `개요`가 선택되어 있다.

구성:

- Gmail 연결 카드
- 최근 분석 시작 카드
- 구조화 테스트 소개 카드
- 왼쪽 메일 목록 영역의 빈 상태 안내

주요 CTA:

```text
[최근 50개 분석 시작] [Gmail 다시 가져오기] [개수 50]
```

분석 시작 후:

```text
LLM 구조화 중
현재 단계: structuring
run: mail_run_xxx
```

### 분석 후

중앙 워크벤치에는 분석 요약과 다음 테스트 CTA가 보인다.
왼쪽 Mail Side Panel에는 최근 분석된 메일 목록이 표시된다.

요약 지표:

- 전체 thread
- 구조화 완료
- 주의 필요
- 첨부파일
- 요청사항
- 일정
- 테스트 상태
- 개선 후보

주요 CTA:

```text
[구조화 테스트 시작]
```

## 5.2 최근 분석

### 목적

최근 N개 메일이 어떻게 구조화되었는지 표와 상세로 확인한다.
기본 분석은 워크스페이스 `.haro/cache` snapshot을 우선 사용하고, `Gmail 다시 가져오기`를 눌렀을 때만 Gmail API를 강제로 호출한다.

### 상단 요약

```text
전체 thread 50
구조화 완료 47
주의 필요 3
첨부파일 36
요청사항 58
일정 19
카테고리 6
```

### 탭

`최근 분석` 화면 내부에는 보조 탭을 둔다.

- `보낸사람`
- `카테고리`
- `Thread`
- `첨부파일`
- `주의 항목`

이 보조 탭은 중앙 워크벤치 안에서만 동작한다.
최상단 메뉴의 `최근 분석`과 혼동되지 않게 시각적으로 작게 표현한다.

### 보낸사람 탭

컬럼:

- 보낸사람
- 도메인
- thread 수
- 요청사항 수
- 첨부 수
- 대표 카테고리
- 품질

품질 표시:

- `좋음`
- `보통`
- `주의`
- `제외 적합`

### 카테고리 탭

컬럼:

- 카테고리
- thread 수
- 요청사항 수
- 일정 수
- 첨부 수
- 품질

카테고리를 클릭하면 해당 카테고리의 thread 목록을 필터링한다.

### Thread 탭

컬럼:

- 상태
- 카테고리
- 제목
- 보낸사람
- 수신일
- 요청사항
- 일정
- 첨부 수
- 요약

상태 badge:

- `좋음`
- `주의`
- `요약 부족`
- `일정 불명확`
- `결과물 불명확`

thread를 클릭하면 상세 패널이 열린다.
동시에 왼쪽 Mail Side Panel의 선택 메일도 해당 thread로 바뀐다.

### 첨부파일 탭

컬럼:

- 파일 제목
- 확장자
- 용량
- 연결 thread
- 보낸사람
- 요약 가능 여부
- 요약 상태
- 핵심 내용

요약 제외 파일은 이유를 명확히 표시한다.

예:

```text
banner.zip
요약 제외
zip 파일은 v1에서 내용 요약 대상이 아닙니다.
```

### 주의 항목 탭

컬럼:

- 제목
- 보낸사람
- 주의 이유
- 누락 정보
- 추천 후속 질문
- 개선 후보 저장

주의 이유 예:

- 결과물이 불명확함
- 일정 표현이 상대적임
- 이전 thread 참조가 필요함
- 첨부파일 내용을 읽을 수 없음
- 요청 주체가 불명확함

## 5.3 구조화 테스트

### 목적

사용자가 실제 업무 질문으로 구조화 품질을 테스트한다.

### 화면 구조

```text
[상단 메뉴]

구조화 테스트
최근 분석 결과가 업무 질문에 잘 답하는지 확인하세요.

[자연어 검색창]

추천 테스트 질문
┌ 질문 카드 ┐ ┌ 질문 카드 ┐ ┌ 질문 카드 ┐

최근 테스트 결과
```

왼쪽 Mail Side Panel에서 메일이 선택되어 있으면 검색창 위에 선택 메일 context chip을 표시한다.

예:

```text
선택 메일 기준으로 질문 중:
[A광고주] 5월 2주차 성과 보고 요청  [해제]
```

### 자연어 검색창

placeholder:

```text
예: 이번 주 A광고주가 요청한 성과 보고 관련 메일 찾아줘
```

입력 후 Enter 또는 `테스트 실행` 버튼으로 실행한다.

### 추천 질문 카드

카드 예:

```text
고객별 요청 검색
이번 주 A광고주가 요청한 성과 보고 관련 메일 찾아줘
```

```text
마감 기반 검색
금요일까지 해야 하는 요청만 모아줘
```

```text
첨부 기반 검색
첨부된 엑셀 파일들이 어떤 지표를 담고 있는지 요약해줘
```

질문 카드를 클릭하면 검색창에 질문이 들어가고 바로 실행된다.

### 결과 영역

검색 결과는 다음 구조로 표시한다.

```text
검색 결과 3개

[결과 카드]
제목
카테고리
요청사항
일정
첨부
요약
근거
품질
```

각 결과 카드에는 `근거 보기` 버튼이 있다.
결과 카드를 클릭하면 왼쪽 Mail Side Panel의 선택 메일이 해당 결과 thread로 바뀐다.

### 품질 판단 액션

사용자는 테스트 결과에 대해 간단한 판단을 남길 수 있다.

- `정확함`
- `일부 아쉬움`
- `부정확함`
- `개선 후보로 저장`

이 판단은 `테스트 결과` 화면에 누적된다.

## 5.4 자연어 검색

### 목적

구조화된 메일 인덱스를 업무 언어로 검색한다.
검색은 ChromaDB 기반 vector hit와 기존 텍스트 점수를 결합한 hybrid ranking을 우선 사용한다.
벡터 검색을 사용할 수 없는 환경에서는 기존 텍스트 검색 fallback으로 동작한다.

### 검색 유형

- 고객/조직 기반
- 보낸사람 도메인 기반
- 카테고리 기반
- 요청사항 기반
- 일정/마감 기반
- 첨부파일 기반
- 구조화 주의 항목 기반

### 검색 결과 카드

카드 구성:

```text
[상태 badge] [카테고리]
제목
검색 방식: vector 92% 또는 text fallback

요청사항:
...

일정:
...

첨부:
...

근거:
- 제목 매칭
- sender domain 매칭
- 본문에서 요청사항 추출

[상세 보기] [개선 후보로 저장]
```

`상세 보기`를 누르면:

- 왼쪽 Mail Side Panel에서 해당 메일 상세가 열린다.
- 중앙 워크벤치에는 검색 근거와 구조화 필드가 유지된다.
- 오른쪽 채팅에는 “이 결과에 대해 이어서 질문”할 수 있는 컨텍스트가 붙는다.

결과가 없을 때:

```text
검색 결과가 없습니다.
다른 표현으로 질문하거나, 분석 범위를 확인하세요.
```

## 5.5 인사이트

### 목적

여러 메일을 묶어 반복 패턴, 마감 집중, 고객별 리스크를 보여준다.

### 화면 구조

```text
인사이트

[인사이트 질문 입력]

추천 인사이트
- 이번 주 고객들이 반복해서 요구한 것은 뭐야?
- 이번 주 A광고주 관련해서 놓치면 위험한 게 뭐야?
- 구조화가 애매하거나 자신 없는 항목만 보여줘

인사이트 결과
```

### 인사이트 결과 구조

```text
요약 결론

1. 반복 패턴 제목
   설명
   관련 고객
   근거 thread 수
   대표 thread

2. 반복 패턴 제목
   ...

주의 / 개선 후보
```

각 인사이트 항목은 근거 thread를 펼쳐볼 수 있어야 한다.
근거 thread를 클릭하면 왼쪽 Mail Side Panel에서 해당 메일 상세가 열린다.

### 인사이트 유형별 UI

반복 요청:

- 패턴명
- 등장 횟수
- 관련 고객
- 대표 thread

고객별 리스크:

- 고객명
- 위험 요약
- 마감
- 누락 정보
- 관련 첨부

구조화 오류:

- 오류 유형
- 항목 수
- 대표 thread
- 개선 후보

## 6. 오른쪽 채팅 패널 연동

메일 관리 화면에서도 오른쪽 채팅 패널은 유지된다.
중앙 워크벤치와 오른쪽 채팅은 서로 독립된 화면이 아니라 같은 분석 run과 선택 메일을 공유한다.

### 상호작용 원칙

- 왼쪽에서 메일을 선택하면 오른쪽 채팅은 선택 메일을 현재 컨텍스트로 인식한다.
- 중앙 워크벤치에서 자연어 검색을 실행하면 같은 query가 채팅 히스토리에 남거나 연결된다.
- 오른쪽 채팅에서 메일 관련 질문을 하면 중앙 워크벤치의 현재 상단 메뉴가 `자연어 검색` 또는 `인사이트`로 전환될 수 있다.
- 메일 관리 화면에서 오른쪽 채팅에 질문을 보낼 때는 latest analysis run과 선택 thread context를 함께 전달한다.
- 메일 관련 질문은 파일 업로드/파일 경로 요청으로 빠지지 않고 Gmail 분석 검색 결과를 근거로 답해야 한다.
- 채팅 입력창에는 선택 thread/run을 보여주는 context chip을 표시한다.
- 사용자가 보낸 메시지에는 어떤 메일 컨텍스트로 질문했는지 작은 `메일:` 표시를 남긴다.
- context chip의 `워크벤치에서 보기` 버튼은 메일 워크벤치를 다시 활성화한다.
- 채팅 답변의 결과 thread를 클릭하면 왼쪽 Mail Side Panel의 메일 상세가 열린다.
- 채팅 답변에서 생성한 개선 후보는 `테스트 결과` 메뉴에 반영된다.

채팅 입력 예:

```text
이번 주 A광고주가 성과 보고와 관련해서 요청한 것만 찾아줘.
```

```text
이번 분석에서 구조화가 애매한 메일만 모아서 이유별로 정리해줘.
```

```text
고객들이 반복적으로 요청한 걸 기준으로 다음 주 업무 리스크를 알려줘.
```

채팅 응답은 중앙 워크벤치와 연결되어야 한다.

연결 방식:

- 채팅 답변에서 `워크벤치에서 보기` 버튼 제공
- 채팅 답변에서 `메일 상세 보기` 버튼 제공
- 중앙 자연어 검색 결과에 같은 query 표시
- 인사이트 결과를 중앙 `인사이트` 화면에 저장 가능
- 개선 후보를 `테스트 결과` 화면에 추가 가능

### 중앙 워크벤치에서 채팅으로 보내기

중앙 결과 카드에는 다음 액션을 제공한다.

- `이 결과로 질문하기`
- `이 메일 기준으로 질문하기`
- `이 인사이트를 채팅에 공유`

예:

```text
[A광고주] 5월 2주차 성과 보고 요청
[상세 보기] [이 메일 기준으로 질문하기]
```

`이 메일 기준으로 질문하기`를 클릭하면 오른쪽 채팅 입력창이 다음 상태가 된다.

```text
선택 메일: [A광고주] 5월 2주차 성과 보고 요청
이 메일에 대해 질문하세요...
```

## 7. 상태 설계

### 상태 목록

`testing`:

`test_complete`:

- 테스트 요약

`error`:

## 9. 시각 디자인 방향

메일 관리는 B2B 운영 도구 화면이다.
마케팅 랜딩 페이지처럼 보이면 안 된다.

디자인 원칙:

- 조용하고 밀도 있는 정보 배치
- 표, 필터, 상태 badge 중심
- 불필요한 장식 최소화
- 중요한 CTA는 한 화면에 하나만 강조
- 카드 남발 금지
- 데이터 테이블과 상세 패널의 대비 명확화
- 상태 색상은 제한적으로 사용

상태 색상:

- `좋음`: green 계열
- `보통`: blue 또는 neutral
- `주의`: amber
- `오류`: red
- `제외/요약 불가`: gray

## 10. 접근성과 사용성

- 모든 주요 버튼은 텍스트와 아이콘을 함께 사용한다.
- 검색창은 Enter 실행을 지원한다.
- 추천 질문 카드는 키보드 포커스가 가능해야 한다.
- 결과 카드의 `근거 보기`는 버튼으로 제공한다.
- table row 클릭 외에도 명시적 `상세 보기` 버튼을 둔다.
- 구조화 상태 badge는 색상만으로 의미를 전달하지 않고 텍스트를 포함한다.
- 긴 제목, 이메일 주소, 파일명은 ellipsis 처리하되 tooltip으로 전체를 볼 수 있게 한다.

### 좁은 화면

- 메일 탐색의 목록/상세 2열은 좁은 화면에서 1열로 접힌다.
- 검색 결과와 인사이트 카드는 화면 폭에 맞춰 세로로 배치한다.
- 메일 상세의 메타 정보 grid는 모바일 폭에서 1열로 전환한다.
- 채팅 입력의 context chip과 전송 버튼은 세로로 접혀 텍스트가 겹치지 않게 한다.
- 상단 탭과 분석 컨트롤은 줄바꿈을 허용하되 버튼 텍스트가 부모 영역을 넘지 않게 한다.

## 11. 구현 시 컴포넌트 초안

구현 시 다음 컴포넌트 분리를 권장한다.

```text
WorkspaceMailShell
  MailSidePanel
    MailThreadList
    MailThreadDetail
  MailWorkbench
    MailTopMenu
    MailContextBar
    MailOverview
    MailAnalysisDashboard
    MailStructuredThreadTable
    MailAttachmentTable
    MailStructureTest
    MailNaturalSearch
    MailInsightPanel
    MailTestResult
    MailDetailDrawer
```

역할:

- `WorkspaceMailShell`: 메일 관리 모드 전체 조립
- `MailSidePanel`: Gmail 상태, 메일 목록, 선택 메일 상세
- `MailThreadList`: 최근 분석된 thread 목록과 필터
- `MailThreadDetail`: 선택한 메일의 구조화 상세
- `MailWorkbench`: 상단 메뉴와 중앙 작업 화면 조립
- `MailTopMenu`: 개요/최근 분석/구조화 테스트/자연어 검색/인사이트/테스트 결과 탭
- `MailContextBar`: 선택 메일, 최근 질문, 분석 run 표시
- `MailAnalysisDashboard`: 최근 분석 통계
- `MailStructuredThreadTable`: thread 구조화 결과
- `MailAttachmentTable`: 첨부파일 구조화 결과
- `MailStructureTest`: 추천 질문과 테스트 실행
- `MailNaturalSearch`: 자연어 검색 결과
- `MailInsightPanel`: 인사이트 결과
- `MailTestResult`: 성공/주의/실패와 개선 후보
- `MailDetailDrawer`: thread/result/insight 상세
