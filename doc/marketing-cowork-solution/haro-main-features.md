# 하로 주요 기능과 대표 사용예시

## 1. 문서 목적

이 문서는 사용자 시나리오를 바탕으로 하로의 주요 기능을 정리한다.

핵심 관점은 다음이다.

```text
하로의 본질은 보고서 생성, 소재 생성, 알림 생성이 아니다.

하로의 본질은 사용자의 업무규칙을 학습하고 기억하는 것이다.
그게 되면 보고서, 소재, 알림, 상황판, 인수인계는 모두 파생된다.
```

따라서 이 문서는 기능을 병렬로 나열하지 않는다.

먼저 하로의 원천 기능인 `업무규칙 학습과 기억`을 정의하고, 그 위에서 어떤 사용예시가 파생되는지 정리한다.

## 2. 하로의 제품 정의

하로는 마케팅 팀과 광고주가 일하는 방식을 배우고 기억하는 AI 코워크 솔루션이다.

하로가 기억해야 하는 것은 단순한 파일이나 대화 기록이 아니다. 더 중요한 것은 사용자가 반복해서 적용하는 업무규칙이다.

예를 들면 다음과 같다.

- 이 광고주는 보고서에서 액션 플랜을 먼저 보고 싶어 한다.
- 네이버 리포트의 `장바구니금액`은 매출로 쓰면 안 된다.
- Meta 신규 소재는 CPA가 기존 대비 20% 이상 낮으면 예산 증액 후보로 본다.
- 이 브랜드는 `싸다`는 표현을 싫어하고 `부담 없이 경험한다`는 표현을 선호한다.
- 정기배송 해지 불만이 늘면 CS 이슈가 아니라 광고 전환율 리스크로도 본다.
- 민서가 맡던 A광고주는 매주 금요일 4시에 ROAS, 소재별 CPA, 다음 주 예산 조정안을 본다.

하로의 제품 정의는 다음처럼 정리할 수 있다.

```text
하로는 사용자의 업무규칙을 대화, 자료, 피드백, 실행 이력에서 학습하고,
그 기억을 바탕으로 반복 업무와 의사결정 보조를 수행하는
AI 마케팅 코워크 솔루션이다.
```

## 3. 핵심 기능: 업무규칙 학습과 기억

하로의 최상위 기능은 하나다.

```text
업무규칙을 학습하고 기억한다.
```

여기서 업무규칙은 사용자가 매번 명시적으로 말하지 않아도 실제 업무에서 반복 적용되는 기준, 방식, 선호, 예외, 판단 로직을 뜻한다.

하로가 이 규칙을 잘 배울수록 사용자는 매번 같은 설명을 반복하지 않아도 된다.

### 3.1 업무규칙의 종류

하로가 기억해야 할 업무규칙은 크게 여섯 가지다.

| 규칙 유형 | 의미 | 예시 |
| --- | --- | --- |
| 데이터 규칙 | 자료를 어떻게 읽고 해석할지에 대한 규칙 | 어떤 컬럼을 매출로 볼지, 어떤 값은 제외할지 |
| 산출물 규칙 | 보고서, 대시보드, 문서의 구성 방식 | 액션 플랜을 맨 위에 둘지, 어떤 지표를 반드시 넣을지 |
| 판단 규칙 | 성과와 리스크를 해석하는 기준 | CPA 상승을 어느 정도부터 문제로 볼지 |
| 메시지 규칙 | 브랜드와 광고주가 선호하는 표현 방식 | 금지 표현, 선호 톤, 카피 스타일 |
| 실행 규칙 | 업무를 언제, 어디서, 어떤 순서로 처리할지 | 금요일 보고, 카톡 파일 수신, 공유 링크 생성 |
| 팀 맥락 규칙 | 사람과 계정별 히스토리와 업무 방식 | 담당자별 진행 상황, 광고주별 선호, 이전 반려 사유 |

### 3.2 업무규칙 학습 루프

하로는 처음부터 완성된 자동화 템플릿을 제공하는 방식이 아니다.

사용자의 실제 자료와 피드백을 통해 규칙을 배운다.

기본 학습 루프는 다음과 같다.

```text
사용자가 힘든 일을 자연어로 말한다
  -> 하로가 필요한 질문을 한다
  -> 사용자가 실제 자료를 올린다
  -> 하로가 초안을 만든다
  -> 사용자가 맞다/아니다를 피드백한다
  -> 하로가 업무규칙을 저장한다
  -> 다음 작업부터 같은 규칙을 적용한다
  -> 새 피드백이 들어오면 규칙을 갱신한다
```

이 루프가 하로의 핵심이다.

보고서 생성은 이 루프의 결과물이고, 소재 생성도 이 루프의 결과물이다. 중요한 것은 산출물 그 자체가 아니라, 산출물을 만드는 기준이 점점 사용자의 방식에 맞춰진다는 점이다.

### 3.3 좋은 기억과 나쁜 기억

하로가 단순히 모든 대화를 저장한다고 해서 좋은 제품이 되지는 않는다.

좋은 기억은 다음 조건을 만족해야 한다.

- 다음 작업에서 실제로 재사용된다.
- 사용자가 다시 설명하지 않아도 같은 기준이 적용된다.
- 언제, 누구에게, 어떤 범위에서 적용되는 규칙인지 구분된다.
- 틀린 피드백을 받으면 수정된다.
- 오래된 규칙과 최신 규칙이 충돌할 때 최신 맥락을 우선한다.

반대로 나쁜 기억은 다음과 같다.

- 대화 기록은 많지만 다음 실행에 반영되지 않는다.
- 광고주 A의 규칙을 광고주 B에게 잘못 적용한다.
- 사용자가 한 번 말한 임시 지시를 영구 규칙처럼 적용한다.
- 틀린 판단을 했는데도 같은 실수를 반복한다.

하로의 핵심 품질은 결국 기억의 양이 아니라, 업무규칙의 정확도와 적용 범위다.

## 4. 업무규칙에서 파생되는 기능

아래 기능들은 모두 독립적인 핵심 기능이라기보다, 업무규칙 학습과 기억에서 파생되는 실행 능력이다.

### 4.1 자료 수집과 정규화

자료 정리는 데이터 규칙의 파생 기능이다.

하로가 다음을 기억하면 매체별 파일이 달라도 반복해서 정리할 수 있다.

- 매체별 컬럼명이 무엇을 뜻하는지
- 어떤 컬럼을 매출, 비용, 전환으로 볼지
- 어떤 데이터는 제외해야 하는지
- 광고주별로 어떤 지표를 중요하게 보는지

따라서 자료 정규화의 핵심은 파서가 아니라, 사용자별 데이터 해석 규칙이다.

### 4.2 성과 분석

성과 분석은 판단 규칙의 파생 기능이다.

ROAS, CPA, 전환율 같은 숫자는 누구에게나 같아 보이지만, 실제 판단 기준은 광고주와 브랜드마다 다르다.

하로가 기억해야 하는 것은 다음과 같다.

- 이 계정에서 정상 CPA 범위는 어느 정도인지
- 어떤 캠페인은 단기 ROAS보다 신규 고객 확보가 더 중요한지
- 어떤 소재는 학습 기간을 더 길게 봐야 하는지
- 예산 증액이나 중단을 제안하는 기준은 무엇인지

이 판단 규칙이 있어야 하로의 분석이 일반론이 아니라 실제 업무 판단에 가까워진다.

### 4.3 고객 반응 분석

고객 반응 분석은 메시지 규칙과 판단 규칙의 파생 기능이다.

하로는 리뷰, 댓글, CS 메일을 단순히 긍정/부정으로 나누는 데서 그치면 안 된다.

중요한 것은 그 반응이 어떤 업무 의미를 가지는지 해석하는 것이다.

예를 들어 `달다`는 리뷰는 다음처럼 다르게 해석될 수 있다.

| 맥락 | 해석 |
| --- | --- |
| 광고 메시지가 `가볍다`를 강조한 경우 | 메시지와 실제 경험의 충돌 |
| 상세페이지에 맛 설명이 부족한 경우 | 구매 전 기대 조정 실패 |
| 반복 빈도가 높고 평점이 낮은 경우 | 상품 개선 후보 |
| 일부 세그먼트에서만 나타나는 경우 | 타깃 또는 소재 메시지 조정 후보 |

이 차이를 만들려면 하로가 브랜드별 메시지 규칙과 상품 맥락을 기억해야 한다.

### 4.4 액션 제안

액션 제안은 판단 규칙과 실행 규칙의 파생 기능이다.

하로가 좋은 액션을 제안하려면 단순히 문제가 무엇인지 아는 것만으로는 부족하다.

다음을 기억해야 한다.

- 이 팀이 실제로 이번 주에 바꿀 수 있는 것은 무엇인지
- 광고 문구 수정, 상세페이지 수정, 상품 개선 중 무엇이 빠른지
- 어떤 액션은 CEO 승인 없이 가능하고, 어떤 액션은 승인이 필요한지
- 이전에 비슷한 제안을 했을 때 결과가 어땠는지

즉, 액션 제안은 지식의 문제가 아니라 실행 맥락의 문제다.

### 4.5 결과물 생성과 공유

보고서, 대시보드, 소재 검토 페이지는 산출물 규칙의 파생 기능이다.

하로가 기억해야 하는 것은 다음이다.

- 누가 이 결과물을 보는지
- 어떤 순서로 보여줘야 설득되는지
- 숫자를 얼마나 자세히 보여줄지
- 액션을 앞에 둘지, 근거를 앞에 둘지
- 링크 공유용인지 내부 검토용인지

같은 데이터라도 CEO용, 광고주용, 실무자용 결과물은 달라야 한다.

이 차이를 만드는 것이 산출물 규칙이다.

### 4.6 광고 소재와 콘텐츠 생성

광고 소재 생성은 메시지 규칙의 파생 기능이다.

하로가 단순히 카피를 많이 만드는 것은 차별점이 아니다.

중요한 것은 다음을 기억하는 것이다.

- 이 브랜드가 쓰면 안 되는 표현
- 이 광고주가 좋아하는 근거 제시 방식
- 과거에 반려된 소재의 이유
- 실제 고객 댓글에서 반복되는 표현
- 성과가 좋았던 메시지 구조

이 기억이 있어야 하로의 소재 제안이 무작위 아이디어가 아니라 팀의 누적 학습이 된다.

### 4.7 위험 신호 감지

위험 신호 감지는 판단 규칙과 실행 규칙의 파생 기능이다.

클레임이 늘었다는 사실 자체보다 중요한 것은 이 변화가 어떤 리스크로 이어질지 판단하는 것이다.

예를 들어 정기배송 해지 불만은 다음 영역에 영향을 줄 수 있다.

- CS 처리량
- 리뷰 평점
- 신규 구매 전환율
- 광고 소재 신뢰도
- 상세페이지 FAQ 구성

하로가 이 연결 관계를 기억하면 단순 알림이 아니라 조기 대응 제안이 된다.

### 4.8 팀 업무 맥락 공유

팀 업무 맥락 공유는 팀 맥락 규칙의 파생 기능이다.

사람이 쉬거나 바뀌어도 일이 이어지려면 다음이 남아 있어야 한다.

- 광고주별 보고 기준
- 현재 진행 상황
- 남은 자료
- 이전 의사결정
- 담당자별 커뮤니케이션 톤
- 다음에 해야 할 일

하로가 이것을 기억하면 인수인계 문서가 따로 없어도 업무가 이어진다.

## 5. 대표 사용예시

아래 항목들은 하로의 독립 기능이라기보다, 업무규칙 기억이 실제 업무에서 드러나는 대표 사용예시다.

### 5.1 주간 성과 보고서 자동 생성

사용자는 매체별 성과 파일을 올리고 다음처럼 요청한다.

```text
하로야, 이번 주 주간 성과 보고서 만들어줘.
광고주 공유용으로.
```

하로는 단순히 파일을 합치는 것이 아니라, 이전에 배운 규칙을 적용한다.

- 어떤 컬럼을 매출로 볼지
- 어떤 지표를 반드시 넣을지
- 어떤 광고주에게 액션 플랜을 먼저 보여줄지
- 어떤 표현으로 성과를 설명할지
- 지난번 피드백에서 무엇을 고쳤는지

그래서 주간 보고서는 하로의 핵심 기능이 아니라, 업무규칙 기억의 대표 결과물이다.

### 5.2 CEO 주간 브랜드 상황판

CEO는 숫자보다 이번 주에 무엇을 봐야 하고 무엇을 결정해야 하는지 알고 싶어 한다.

하로가 기억해야 하는 규칙은 다음이다.

- CEO는 세부 운영 지표보다 우선순위를 먼저 본다.
- 광고 성과와 고객 반응을 분리해서 보면 안 된다.
- CS 이슈가 광고 효율에 영향을 줄 수 있다.
- 상품 개선과 커뮤니케이션 개선을 구분해야 한다.

이 기억이 있으면 하로는 숫자 대시보드가 아니라 의사결정 상황판을 만든다.

### 5.3 댓글/리뷰 기반 광고 소재 기획

하로는 댓글과 리뷰에서 반복 표현을 찾고 광고 소재 방향을 제안한다.

하지만 핵심은 댓글 요약이 아니다.

핵심은 다음 규칙을 기억하는 것이다.

- 어떤 고객 표현이 구매 메시지로 전환될 수 있는지
- 어떤 표현은 상세페이지 FAQ에서 먼저 해소해야 하는지
- 이 브랜드의 톤에 맞는 카피는 무엇인지
- 과거에 성과가 좋았던 메시지 구조는 무엇인지

이 규칙이 있어야 고객 반응이 광고 아이디어로 바뀐다.

### 5.4 리뷰 기반 상품 개선 회의 안건 생성

하로는 리뷰에서 반복 불만을 뽑아 상품 개선 회의 안건으로 정리한다.

이때 중요한 규칙은 다음이다.

- 상품 자체를 바꿔야 하는 불만인지
- 상세페이지 설명으로 해결 가능한 불만인지
- CS 안내 문구로 줄일 수 있는 불만인지
- 빈도는 낮지만 치명적인 불만인지

하로가 이 판단 기준을 기억하면 리뷰는 단순 VOC 요약이 아니라 제품 로드맵 후보가 된다.

### 5.5 클레임 증가 조기 알림

하로는 특정 클레임이 늘면 먼저 알려준다.

하지만 중요한 것은 알림 자체가 아니라, 어떤 증가를 위험 신호로 볼지 기억하는 것이다.

예를 들어 다음 규칙이 필요하다.

- 전주 대비 몇 퍼센트 증가하면 알림을 보낼지
- 단순 문의와 평판 리스크를 어떻게 구분할지
- 광고 소재, 상세페이지, CS 템플릿 중 어디를 먼저 고칠지
- 누구에게 공유해야 하는지

이 규칙이 있어야 클레임 알림이 업무에 실제로 쓰인다.

### 5.6 담당자 부재 시 업무 이어받기

팀원이 휴가나 병가로 자리를 비우면 다른 사람이 하로에게 묻는다.

```text
하로야, 오늘 민서가 쉬어.
A광고주 주간 보고서 내가 대신 봐야 해.
민서가 하던 방식대로 진행 상황 정리해줘.
```

하로가 답하려면 다음을 기억해야 한다.

- 민서가 어디까지 작업했는지
- A광고주의 보고 기준은 무엇인지
- 아직 빠진 자료는 무엇인지
- 이번 주 꼭 확인해야 할 지표는 무엇인지
- 민서가 쓰던 보고서 톤과 형식은 무엇인지

이 사용예시는 하로가 단순 자동화 도구가 아니라 팀의 업무 기억이라는 점을 가장 잘 보여준다.

### 5.7 대행사 보고서 검토와 질문 생성

광고주는 대행사 보고서를 하로에게 검토시킨다.

하로가 좋은 질문을 만들려면 다음을 기억해야 한다.

- 우리 브랜드가 이번 주 특히 신경 쓰는 이슈
- 대행사 보고서에서 반복적으로 빠지는 항목
- 광고 성과와 고객 반응 사이의 연결
- CEO가 회의에서 확인해야 하는 질문

따라서 대행사 보고서 검토도 문서 요약 기능이 아니라, 업무 맥락 기억의 파생 사용예시다.

## 6. 제품 설계 원칙

하로를 설계할 때 가장 중요한 원칙은 다음이다.

```text
기능을 많이 만드는 것이 아니라,
업무규칙을 잘 배우고 정확히 다시 쓰는 기억 엔진을 만든다.
```

이 원칙에서 몇 가지 제품 방향이 나온다.

### 6.1 모든 실행은 규칙을 남겨야 한다

하로가 보고서를 만들거나 소재를 제안한 뒤에는 결과물만 남기면 안 된다.

어떤 기준으로 그렇게 만들었는지 규칙이 남아야 한다.

예를 들면 다음과 같다.

- 이번 보고서에서 어떤 컬럼 매핑을 썼는가
- 사용자가 어떤 표현을 수정했는가
- 어떤 액션 제안이 승인되었는가
- 어떤 제안은 반려되었고 이유가 무엇인가

### 6.2 피드백은 산출물 수정이 아니라 규칙 수정이어야 한다

사용자가 `이 광고주는 숫자보다 액션을 먼저 봐요`라고 말하면, 현재 보고서만 고치면 안 된다.

하로는 다음 규칙을 저장해야 한다.

```text
이 광고주 보고서에서는 액션 플랜을 지표 요약보다 먼저 배치한다.
```

그래야 다음 보고서부터 같은 실수를 하지 않는다.

### 6.3 규칙에는 적용 범위가 있어야 한다

모든 기억이 전역 규칙이 되면 위험하다.

하로는 규칙의 적용 범위를 구분해야 한다.

| 적용 범위 | 예시 |
| --- | --- |
| 사용자 | 지윤 팀장은 보고서 초안을 짧게 보는 것을 선호한다. |
| 팀 | 이 팀은 금요일 오전에 주간 보고서를 만든다. |
| 광고주 | A광고주는 액션 플랜을 먼저 본다. |
| 브랜드 | 이 브랜드는 저가 이미지를 싫어한다. |
| 매체 | 네이버 파일의 특정 컬럼은 매출로 쓰지 않는다. |
| 프로젝트 | 이번 캠페인은 신규 고객 확보가 ROAS보다 중요하다. |

### 6.4 규칙은 충돌하고 갱신될 수 있어야 한다

업무 방식은 바뀐다.

예전에 맞았던 규칙이 지금은 틀릴 수 있다.

따라서 하로는 다음을 다룰 수 있어야 한다.

- 오래된 규칙과 새 규칙의 충돌
- 일회성 지시와 반복 규칙의 구분
- 사용자가 명시적으로 정정한 규칙의 우선 적용
- 확신이 낮은 규칙에 대한 재확인

## 7. 우선 구현 후보

초기 제품 또는 POC에서는 `주간 성과 보고서 자동 생성`을 가장 먼저 검증할 수 있다.

다만 성공 기준은 보고서가 예쁘게 나오는 것이 아니다.

진짜 성공 기준은 다음이다.

```text
사용자의 피드백이 업무규칙으로 저장되고,
다음 주 보고서에 같은 규칙이 자동으로 반영되는가?
```

초기 검증 루프는 다음처럼 잡을 수 있다.

| 단계 | 검증할 것 |
| ---: | --- |
| 1 | 사용자가 자연어로 업무를 설명한다. |
| 2 | 하로가 자료와 산출물 기준을 질문한다. |
| 3 | 샘플 파일을 받아 첫 보고서를 만든다. |
| 4 | 사용자가 컬럼 해석, 표현, 구성에 대해 피드백한다. |
| 5 | 하로가 피드백을 업무규칙으로 저장한다. |
| 6 | 같은 유형의 새 자료를 넣었을 때 저장된 규칙을 적용한다. |
| 7 | 사용자가 다시 설명하지 않아도 결과물이 개선되어 나온다. |

이 루프가 검증되면 다음 사용예시는 자연스럽게 확장된다.

- CEO 주간 브랜드 상황판
- 댓글/리뷰 기반 광고 소재 기획
- 클레임 증가 조기 알림
- 담당자 부재 시 업무 이어받기
- 대행사 보고서 검토와 질문 생성

## 8. 정리

하로의 핵심은 개별 자동화 기능이 아니다.

하로의 핵심은 다음 문장으로 정리된다.

```text
사용자가 일하는 방식을 업무규칙으로 배우고,
그 규칙을 기억해,
다음 작업을 사용자의 방식대로 수행하는 것.
```

보고서 생성, 소재 생성, 고객 반응 분석, 위험 알림, 인수인계는 모두 이 능력에서 파생된다.

따라서 하로의 제품 기획과 POC는 `무엇을 만들 수 있는가`보다 `무엇을 기억하고 다음번에 더 잘할 수 있는가`를 중심에 두어야 한다.
