# Human Context Analysis / 사람 맥락 분석 스펙

## 1. 목적

사람 맥락 분석은 haro가 파일과 규칙뿐 아니라 사람 사이의 반복되는 업무 맥락을 기억하게 하는 기능이다.

여기서 인간분석은 성격 단정이나 심리 진단이 아니다.
메일, 채팅, 피드백, 승인 이력에서 반복 관찰되는 업무 선호, 커뮤니케이션 방식, 주의점, 관계 히스토리를 숨은 맥락으로 관리하는 것이다.

v1 목표:

- 사용자가 어떤 방식으로 일하기를 선호하는지 기억한다.
- 자주 커뮤니케이션하는 대상이 어떤 형식과 톤을 선호하는지 기억한다.
- 답장 초안, 우선순위 판단, 누락 맥락 보강에만 활용한다.
- 자동 발송, 외부 API 호출, 금액/계약/HR 민감 판단에는 직접 사용하지 않는다.

## 2. 관리 대상

v1은 모든 등장인물을 무제한으로 분석하지 않는다.
관리 대상은 두 가지다.

| 대상 | 의미 |
| --- | --- |
| `self_profile` | 현재 haro 사용자 자신의 업무 선호와 승인 성향 |
| `contact_profile` | 메일/채팅에서 자주 등장하는 주요 커뮤니케이션 대상 |

`contact_profile`은 고객, 광고주 담당자, 매체 담당자, 내부 승인자, HR 문의자, 거래처 담당자처럼 반복 업무 흐름에 영향을 주는 사람만 만든다.

일회성 발신자, 뉴스레터 발신자, 시스템 알림 계정은 기본적으로 사람 맥락을 만들지 않는다.

## 3. 저장 위치

사람 맥락은 Clean Room 공식 기준이 아니다.
또한 User Playground의 자유 실험 산출물도 아니다.

숨은 맥락 저장소는 `.haro/context/` 아래에 둔다.

```text
.haro/
  context/
    self/
      {user_id}.json
    contacts/
      {contact_hash}.json
    source-refs/
      {ref_id}.json
```

저장 원칙:

- 원문 전체를 저장하지 않는다.
- 이메일 주소와 실명은 최소화하고, 필요하면 hash 또는 내부 id로 참조한다.
- 맥락 항목은 요약과 근거 참조만 가진다.
- 사용자가 열람, 수정, 삭제, 비활성화할 수 있어야 한다.
- Project Fork, template package, Clean Room Git에는 포함하지 않는다.

## 4. 사람 맥락 모델

모든 맥락 항목은 다음 공통 필드를 가진다.

| 필드 | 의미 |
| --- | --- |
| `summary` | 사람이 읽을 수 있는 짧은 맥락 요약 |
| `confidence` | 관찰 근거의 신뢰도 |
| `last_seen` | 마지막으로 관찰된 시각 |
| `source_refs` | 원문이 아니라 근거 snapshot 또는 thread 요약 참조 |
| `user_verified` | 사용자가 확인/수정했는지 여부 |
| `disabled` | 이 맥락을 더 이상 사용하지 않을지 여부 |

### `self_profile`

사용자 자신에 대한 맥락이다.

예:

```json
{
  "profile_type": "self_profile",
  "user_id": "jiyoon",
  "preferences": [
    {
      "summary": "고객 메일은 자동 발송하지 않고 초안만 만들기를 선호한다.",
      "confidence": 0.95,
      "last_seen": "2026-04-29T10:00:00+09:00",
      "source_refs": ["chat-session-20260429-001"],
      "user_verified": true,
      "disabled": false
    },
    {
      "summary": "광고주 보고서는 숫자보다 다음 액션을 먼저 검토한다.",
      "confidence": 0.82,
      "last_seen": "2026-04-29T11:20:00+09:00",
      "source_refs": ["report-feedback-001"],
      "user_verified": false,
      "disabled": false
    }
  ]
}
```

관리할 수 있는 사용자 맥락:

- 선호하는 업무 방식
- 승인 성향
- 자주 쓰는 톤
- 업무 시간대
- 반복 피드백
- 싫어하는 출력 방식
- 자동화 금지 선호

### `contact_profile`

커뮤니케이션 대상에 대한 맥락이다.

예:

```json
{
  "profile_type": "contact_profile",
  "contact_id": "contact-a-client-manager",
  "display_hint": "A광고주 김민지 매니저",
  "relationship": "advertiser_contact",
  "observations": [
    {
      "summary": "보고서 첫 장에 숫자보다 다음 주 액션 플랜을 먼저 보는 편이다.",
      "confidence": 0.86,
      "last_seen": "2026-04-22T16:30:00+09:00",
      "source_refs": ["gmail-thread-summary-20260422-002"],
      "user_verified": true,
      "disabled": false
    },
    {
      "summary": "일정이 빠진 답변에는 추가 확인 메일을 보내는 경우가 많다.",
      "confidence": 0.74,
      "last_seen": "2026-04-25T09:10:00+09:00",
      "source_refs": ["gmail-thread-summary-20260425-001"],
      "user_verified": false,
      "disabled": false
    }
  ]
}
```

관리할 수 있는 대상 맥락:

- 소속과 역할
- 자주 요청하는 일
- 선호하는 답변 형식
- 민감한 주제
- 과거 합의
- 응답 지연/긴급도 패턴
- 누락 정보에 대한 반응 패턴

## 5. Gmail CRM 인박스 연동

Gmail thread를 해석할 때 haro는 발신자와 수신자의 기존 사람 맥락을 참고할 수 있다.

활용 예:

- “이 광고주는 액션 먼저 보는 편”이면 보고서 초안의 첫 문단에 다음 액션을 먼저 배치한다.
- “이 담당자는 일정 명시를 중요하게 봄”이면 응답 초안에 예상 완료 시각과 다음 확인 시점을 넣는다.
- “사용자는 자동 발송을 원하지 않음”이면 Gmail 초안만 만들고 발송 액션을 제안하지 않는다.

메일 상세 화면에는 다음처럼 요약만 노출한다.

```text
haro가 참고한 사람 맥락

- A광고주 김민지 매니저는 보고서 첫 장에 액션 플랜을 먼저 보는 편입니다.
- 이 관찰은 사용자가 2026-04-22에 확인했습니다.
- 이 맥락을 이번 초안에 사용했습니다.

[수정] [이번에는 사용하지 않기] [삭제]
```

## 6. 스킬과 Workflow 연동

workflow의 LLM 태스크는 선택적으로 `human_context`를 입력으로 받을 수 있다.

예:

- 광고주 보고서 공유 코멘트 생성
- HR 민감 문의 응답 초안
- 고객 CS 답변 톤 조정
- 거래처 일정 확인 메일 초안

태스크 입력 예:

```json
{
  "task_id": "draft_reply",
  "type": "llm",
  "input": {
    "email_summary": "A광고주가 금요일까지 주간 보고서를 요청했다.",
    "human_context": {
      "self": ["고객 메일은 초안만 만들고 사용자가 직접 발송한다."],
      "contacts": ["A광고주는 액션 플랜을 먼저 보는 편이다."]
    }
  }
}
```

사용 제한:

- 낮은 confidence 맥락은 중요한 결정 근거로 쓰지 않는다.
- `user_verified=false`인 맥락은 초안 표현 보조 정도로만 사용한다.
- 금액, 계약, HR 민감 판단, 자동 발송 여부는 사람 맥락만으로 결정하지 않는다.
- 사람 맥락을 사용한 경우 결과물에 “참고한 맥락”을 남긴다.

## 7. 금지와 허용

### 금지

- 성격 단정
- 심리 진단
- 건강/정치/종교/민감 신원 추정
- 조작적 설득 전략
- 상대의 약점을 이용한 표현 추천
- 사람 맥락을 근거로 자동 발송이나 외부 실행을 결정

### 허용

관찰 가능한 업무 선호와 커뮤니케이션 패턴만 허용한다.

예:

- “A광고주는 보고서 첫 장에 액션 플랜을 선호한다.”
- “B담당자는 일정과 누락 정보를 먼저 확인한다.”
- “사용자는 고객 메일 자동 발송을 원하지 않는다.”
- “이 승인자는 금액 변경이 있으면 근거 파일 링크를 요구하는 편이다.”

## 8. UI 초안

사람 맥락은 기본적으로 배경에서 작동하지만, 완전히 숨기지 않는다.

노출 위치:

- Gmail thread 상세의 “참고한 사람 맥락”
- 응답 초안 옆의 “왜 이렇게 썼나요?”
- 사용자 설정의 “내 업무 선호”
- 연락처 상세의 “관찰된 업무 맥락”

사용자 액션:

- 맥락 수정
- 맥락 삭제
- 특정 연락처 맥락 비활성화
- 이번 응답에서만 사용하지 않기
- 근거 요약 확인

## 9. Project Fork와 보안

Project Fork에는 사람 맥락을 포함하지 않는다.

fork 제외 대상:

- `.haro/context/`
- `self_profile`
- `contact_profile`
- 이메일 주소
- 연락처 id
- 관계 히스토리
- 사람 맥락 source_refs
- 원문 근거
- 사람별 초안/응답 이력

fork에 포함 가능한 것은 일반화된 정책뿐이다.

예:

- “사람 맥락은 요약만 노출한다.”
- “고객 메일은 기본 초안만 만든다.”
- “사람 맥락은 자동 발송 판단에 쓰지 않는다.”

## 10. 성공 기준

- 사용자의 반복 피드백이 `self_profile` 맥락 후보로 저장된다.
- 자주 등장하는 커뮤니케이션 대상의 업무 선호가 `contact_profile` 맥락 후보로 저장된다.
- Gmail 응답 초안에 검증된 사람 맥락을 반영할 수 있다.
- 사용자는 haro가 참고한 사람 맥락 요약을 볼 수 있다.
- 사용자는 사람 맥락을 수정, 삭제, 비활성화할 수 있다.
- 낮은 confidence나 검증되지 않은 추정은 중요한 결정 근거로 쓰이지 않는다.
- 사람 맥락은 Project Fork, template package, Clean Room Git에 포함되지 않는다.
- 성격 단정, 심리 진단, 민감 신원 추정, 조작적 설득 전략을 하지 않는다.
