# 대행사 시나리오 기반 예시 스펙

이 문서는 haro의 대표 적용 예시 중 하나다.
haro는 대행사/마케팅 전용 제품이 아니라, 반복 가능한 workflow와 의사결정 트리를 가진 화이트칼라 업무 전반에 적용되는 솔루션이다.

대행사 시나리오는 파일, 규칙, 판단, 산출물, 고객 커뮤니케이션이 모두 섞여 있어 haro의 핵심 구조를 설명하기 좋은 첫 vertical template example로 사용한다.
한 광고주 프로젝트에서 성공한 workflow meta를 template으로 저장하고, 다른 광고주 프로젝트에 반복 적용하는 확산 구조를 검증하기 좋다.

## 1. 시나리오 핵심

대행사 팀은 전략을 해야 하지만 실제 시간은 엑셀, 캡처, 복붙, 메신저, 보고서 정리에 묶인다.

대행사 시나리오의 핵심 문제:

- 매주 여러 매체 리포트를 받는다.
- 파일 형식과 컬럼명이 다르다.
- 광고주마다 보고서 기준이 다르다.
- 보고서보다 “다음 주에 뭘 바꿀지”가 중요하다.
- 담당자 머릿속에 업무규칙이 쌓인다.
- 휴가나 담당자 변경 시 품질이 흔들린다.

haro는 이 문제를 하네스와 자연어 스킬로 해결한다.

## 2. 주요 인물

| 인물 | 역할 | haro가 도와야 할 일 |
| --- | --- | --- |
| 지윤 | 마케팅 팀장 | 광고주 설득, 팀 운영, 보고 기준 유지 |
| 민서 | 리포트 담당 | 매체별 리포트 취합, 주간 보고서 초안 |
| 도현 | 소재 담당 | 소재 요청서, 카피, 피드백 정리 |
| 수아 | 매체 운영 담당 | 신규 매체 온보딩, 담당자 커뮤니케이션 |

## 3. 핵심 사용자 흐름

### 3.1 첫 자동화

```text
지윤: 매주 금요일마다 매체별 성과 파일 받아서 하나로 합치고,
     광고주한테 보고할 요약 만드는 게 너무 귀찮아요.
```

haro 동작:

1. “주간 광고 성과 보고” 하네스 생성 제안
2. 기본 폴더 구조 생성
3. 샘플 파일 업로드 요청
4. 필요하면 Google Drive 리포트 폴더 연결
5. Excel/CSV 파일 분류
6. 매체별 컬럼 정규화 제안
7. 보고서 초안 생성
8. 사용자 피드백에서 규칙 추출
9. 스킬 초안 저장

### 3.2 파일 업로드와 하네스 정리

사용자가 다음 파일을 올린다.

```text
Meta_Weekly.xlsx
Naver_Search_Report.xlsx
Kakao_Performance.csv
지난주_보고서.pdf
```

또는 Google Drive에 있는 주간 리포트 폴더를 데이터소스로 연결하고, 필요한 파일만 Playground inbox로 가져온다.

haro 제안:

```text
파일을 이렇게 정리할게요.

- clean-room/data/10_sources/media-reports/meta_weekly.csv
- clean-room/data/10_sources/media-reports/naver_search.csv
- clean-room/data/10_sources/media-reports/kakao_performance.csv
- clean-room/data/10_sources/briefs/지난주_보고서.pdf

이번 작업 묶음 이름은 "A광고주 2026-W18 주간 보고"로 둘까요?
```

### 3.3 피드백이 스킬이 되는 순간

사용자 피드백:

```text
여기 매출 컬럼은 네이버 파일에서 구매액이 아니라 장바구니 금액이에요.
그건 빼야 해요.
```

haro 응답:

```text
확인했어요.
이 내용을 네이버 리포트 데이터 규칙으로 저장할까요?

규칙:
- 네이버 리포트에서 장바구니금액은 매출로 사용하지 않는다.
- 구매완료금액만 매출로 본다.

적용 범위:
- A광고주 주간 보고
```

### 3.4 보고서 산출

haro 산출물:

```text
playground/users/jiyoon/30_outputs/drafts/a-client-2026-w18/
  report.md
  dashboard.html
  summary.csv
  advertiser-comment.md
  sources.json
```

사용자는 보고서를 열고, 광고주 공유용 문구를 복사하거나 preview URL을 공유한다.
팀 공식 산출물로 남길 경우 Data Clean Room 승격 요청을 만든다.

### 3.5 담당자 부재 대응

상황:

```text
지윤: 민서가 휴가라서 A광고주 주간 보고서 내가 대신 봐야 해.
```

haro가 알려줘야 할 것:

- A광고주의 보고 일정
- 필요한 입력 파일
- 지난 3주 주요 지표
- 적용할 데이터 규칙
- 보고서 구성 규칙
- 아직 빠진 파일

예시 응답:

```text
A광고주는 매주 금요일 4시에 보고서를 공유합니다.
이번 주 입력 파일 중 네이버 리포트가 아직 없습니다.
지난 3주 기준 A광고주는 다음 세 가지를 꼭 확인합니다.

1. ROAS
2. 소재별 CPA
3. 다음 주 예산 조정안
```

## 4. MVP 업무 템플릿

대행사 example은 네 개 템플릿으로 시작한다.

| 템플릿 | 목적 | 핵심 산출물 |
| --- | --- | --- |
| 주간 성과 보고 | 매체별 성과 취합과 광고주 보고 | 보고서, 대시보드, 공유 코멘트 |
| 소재 요청서 | 광고주/디자이너용 소재 요청 | 소재 브리프, 카피 초안 |
| 성과 이슈 진단 | CPA/ROAS 변동 원인 정리 | 원인 후보, 액션 플랜 |
| 인수인계 요약 | 담당자 부재/교체 대응 | 계정 요약, 진행 상황, 주의 규칙 |

## 4.1 광고주 확산 흐름

대행사에 광고주가 20개 있고, 그중 1개 광고주에 haro 도입이 성공했다고 가정한다.

```text
A광고주 주간 보고 workflow 성공
  -> agency/weekly-report meta template 생성
  -> B~T광고주 프로젝트 생성 시 template 적용
  -> 각 광고주의 Data Clean Room과 User Playground는 독립 유지
```

fork에 포함되는 것:

- 보고 workflow
- 데이터 정규화 규칙
- 보고서 산출물 schema
- validator
- trigger/hook
- 승인 정책

fork에서 제외되는 것:

- A광고주의 실제 성과 데이터
- A광고주의 보고서 결과물
- 개인 playground
- 채팅 원문
- Google Drive 인증 정보와 실제 파일 ID

이 방식으로 대행사용 자동화 template family를 만들고, 같은 구조를 다른 white-collar vertical로 확장한다.

## 5. 화면 흐름

### Step 1. 프로젝트 생성

사용자가 “A광고주 운영” 프로젝트를 만든다.

### Step 2. 업무 하네스 선택

haro가 묻는다.

```text
어떤 일을 자동화하고 싶으세요?

[주간 성과 보고]
[소재 요청서]
[성과 이슈 진단]
[인수인계 요약]
[직접 설명하기]
```

### Step 3. 파일 업로드

사용자는 파일을 드래그앤드랍한다.
또는 Google Drive 데이터소스에서 이번 주 파일을 선택해 가져온다.

### Step 4. 정리 제안

haro가 파일 종류와 폴더 위치를 제안한다.

### Step 5. 첫 실행

haro가 보고서 초안을 만든다.

### Step 6. 피드백 저장

사용자의 수정 요청을 스킬 후보로 저장한다.

### Step 7. 반복 실행

다음 주부터 사용자는 파일을 던지고 “주간 보고서 만들어줘”라고만 말한다.

## 6. MVP 성공 기준

- 신규 사용자가 폴더 구조를 직접 만들지 않아도 시작할 수 있다.
- 업로드 파일이 업무 하네스 안에 정리된다.
- 첫 피드백이 자연어 스킬 후보로 저장된다.
- 다음 실행에서 해당 규칙이 자동 적용된다.
- 산출물은 광고주에게 공유 가능한 형태로 생성된다.
